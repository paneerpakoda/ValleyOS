# Pressure Test — Phase 1 Plan (brainstorm.md)

**Date:** 2026-04-19
**Target:** `brainstorm.md` after PSB Phase 1 Steps 1–11
**Scope:** full plan review before moving to Phase 2 (Setup)

---

## 1. Three most important unanswered questions

1. **Tech stack.** Still undecided. Can't start building. Biggest practical blocker. Choice determines content delivery (baked vs remote), offline story, update cadence, and how you author guide data.
2. **Content authoring workflow.** What does "a task" literally look like as a data artifact? Markdown file? JSON row? If you don't pin this, you end up rebuilding the content layer after writing half the Y1 Spring content.
3. **Atomic task definition.** Is a task "plant 15 parsnips in the tilled patch", or "do farming this morning", or "day 1: complete 3 things"? This is the atom of the whole app and it's not defined. Everything else (checklist, progress, deadlines, bundle links) is downstream of this.

## 2. Weak assumptions / risky areas

- **Phone-as-companion reachability is load-bearing and untested.** Every feature assumes you'll unlock your phone, switch apps, and tap during play. If you don't, the product dies on day one.
- **"Day-level granularity is enough" is the most fragile MVP claim.** By mid-morning on day 3 (rain, festival prep, low energy), a pre-written 5-item morning checklist is stale.
- **Content > app effort, unsized.** Y1 Spring + CC bundles + crop tables + NPC gifts = realistically 80–150 structured tasks and 30+ reference entries. Weeks of writing, not days.
- **"One hardcoded playstyle" hides two layers.** Existing scaffold has "playstyles layer on top of neutral aspect guides." Even a single-playstyle MVP secretly requires the neutral aspect content + one playstyle layer.
- **Mini-wiki scope is undefined and will sprawl.** "Narrow mini-wiki for crops, bundles, core NPCs" is substantial content + a second UI mode.
- **Deviation and catch-up have no design.** What happens when you play 3 in-game days without opening the app?

## 3. Over-scoped for MVP

- **Bundle tracking (light).** Bundle data model + per-bundle progress + turn-in UX. Wiki link only is enough at v0.
- **Crop planning support (light).** Undefined, easy to sprawl. Day tasks cover it at v0.
- **Mini-wiki.** Wiki links are enough until user sees themselves tabbing out despite the links.
- **Deadlines banner.** Pulling from bundles + festivals + birthdays + crop spoilage → deadline aggregation model. Static hand-written weekly list is v0.

## 4. Tighter MVP (pre-MVP spike)

Build **v0 first** to validate the behavioral assumption.

**v0 (the spike):**
- Today view with hardcoded day-indexed tasks for Y1 Spring days 1–7
- Task completion (checkboxes)
- "Advance day" button
- Wiki link per task (external only)
- *No* run concept, *no* playstyle, *no* bundles, *no* mini-wiki, *no* crop planner, *no* banner

Ship v0. Play 3 in-game days. If phone-reach works and value appears → expand.

**v0.1 → v0.3** stage in: bundle references, mini-wiki, crop planner, deadline banner — in the order the user actually misses them.

## 5. Milestone split adjustments

- **Insert v0 spike above MVP.**
- **Stage mini-wiki and bundle tracking behind v0.** Still in MVP scope, but don't commit content effort until phone-reach assumption holds.

Rest of V1/V2/Later/Not-in-Scope split is sound.

## 6. Main risks (ranked)

**Top 3 that can kill the project:**
1. Behavioral: user doesn't reach for phone mid-play (untested, no mitigation planned).
2. Content throughput: Y1 Spring writing takes 3× longer than expected.
3. Day-level granularity inadequate: plan goes stale mid-day, trust erodes.

**Second tier:**
4. Tech stack choice rework.
5. Authoring model not pinned → content rewrites.
6. Scope creep into moment-level guidance.

## 7. Critical note

Plan has a "build whole MVP, then test" shape. For a personal-use app that's backwards — you can ship to yourself on day one. Build a 4-feature v0 in days, not weeks, and let real play kill or confirm the rest.

## Side questions

### What could make the user abandon quickly?
- Stale content (app on day 3, player on day 7)
- Unlock + switch + find-screen slower than Alt-Tab to wiki
- Generic tasks that don't match in-game state
- Too many taps to mark progress
- No clear "today is done" state
- Can't reconcile after a skipped session
- Mini-wiki = wall of text, same problem repackaged

### What's missing from the main user flow?
- Deviation path (didn't plant parsnips day 1 — now what?)
- Catch-up / reconciliation after unlogged play
- End-of-day transition
- Re-order tasks within a day
- Required vs optional distinction per day
- Deadline escalation as CC deadline nears
- First-open-of-day greeting undefined
- "I'm stuck" / skip-without-completing exit

### Assumptions that need real testing (via self-play)
1. Phone-as-companion reach.
2. Day-level granularity sufficiency.
3. Mini-wiki narrowness is correct.
4. Manual bundle tracking doesn't feel like work.
